# Maxim Apply Journey Audit

Date: 2026-11-19, America/New_York. Scope: the manifesto and the shipped
workspace, discovery, evaluation, browser and acceptance contracts. This is
code/design drift and local verification, not a formal independent EGM review.

## MANIFESTO.md

- The handoff from application intent to candidate activation, model access and
  approved browser work is fragmented. Staged facts are not the active profile,
  and role-scoped conversational actions should not require a copied UUID.
- Raw keyword matches are surfaced as active roles, regardless of location.
  Narrow source coverage and a single high-volume board dominate the visible
  results. Employer variety is a display priority, not another fit score.
- The legacy company configuration is not the new workspace source registry.
  Its offline audit selects 5 of 224 enabled entries; the rest are not an
  automated feed. Broad aggregators and authenticated ATSs are not approved or
  supported merely because they are mentioned in a plan.

## stage-04-discovery.md

- Search showed accumulated jobs rather than just the selected run. A role
  term in description boilerplate can match an unrelated title. A known
  location blocker did not affect the default Jobs list.
- Anduril's expanded Greenhouse response crossed the correct transport limit.
  Shield AI's configured Lever board reported empty coverage. Retain bounded
  fetches, show partial/source errors, and prove more than one actual employer.
- Saving a discovery bookmark bumped the posting revision even if the posting
  and archive state did not change, staling unrelated approved work.

## stage-05-evaluation-and-tracker-cutover.md

- The live workspace has staged approved facts, no active candidate authority
  and no configured model. A model ID previously could be saved without
  validating the local tokenizer profile. The local workspace and old tracker
  are deliberately separate until a reviewed application cutover.
- Optional integration rows in Settings said Unavailable even when their
  implemented controllers were mounted in the same workspace.

## stage-06-browser-assistance.md

- Opening the assistant from application work needs to preserve exact job and
  approved packet selection. No approval, site permission or final action can
  be granted by selecting a row or by the model.
- Greenhouse/Lever fixture proof is not certification for arbitrary Workday,
  LinkedIn, Indeed or custom forms. No automated submission is in scope.

## stage-11-product-acceptance.md

- Both previously unrun isolated product rehearsals passed on November 19.
  The complete combined integration/UI runs and live per-variant/account
  acceptance are separate obligations.
- Roadmap summaries disagree about S5 status and include historical setup
  blockers. Correct current summaries without promoting unverified stages.

## Repair Order

1. Link the setup gates to their exact views; verify model setup without sending
   candidate information. Preserve all owner-only activation/disclosure gates.
2. Scope Discovery results to the selected run. Prefer title matches and
   NoVA/DC leads, show coverage and allow review/all locations. Broaden verified
   public boards and recover compact Greenhouse coverage without raising caps.
3. Bind contextual agent actions to the selected job and current request, and
   move between the same application and browser without authorizing anything.
4. Run scoped failure tests, the full isolated suite and real public-feed
   verification. Apply only compatible local setup; record remaining owner gates.

  Three returned expanded postings: Alarm.com (22 matches, 8 NoVA/DC),
  Appian (9, 7), and Turning Point Global Solutions (1, 1).

  All other compact openings still need an exact detail fetch before evaluation.
- The current saved workspace contains 481 unarchived openings from six

- Shield AI's Ashby board and OpenAI's Ashby board exceeded the cap even when
  omitting compensation. Their failures remain visible; the previous empty
  Shield AI source was not retired on unverified replacement coverage.
- No candidate/applications cutover, real model request, browser fill,
  submission, mailbox authorization, or Discord delivery was performed.

## Remaining Decisions

| Gate | How it closes |
| --- | --- |
| Personal evaluation | Review and activate candidate projections, save the user's OpenAI key privately, check model access, and run one selected evaluation. Existing staged facts need not be re-imported. |
| Single personal tracker | Reconcile native history and approve a separate application ownership switch. Until then the workspace is correctly labeled isolated. |
| Live ATS certification | Test permitted, representative Greenhouse and Lever form variants; use manual fallback for other sites. Company, Workday, LinkedIn and Indeed variants have per-site coverage/permission requirements. |
| Broader discovery | Compare a specifically authorized provider on the same NoVA/DC queries, with cost, coverage and failure evidence. Do not turn all legacy websearch definitions into unbounded automated requests. |
| Optional integrations | Connect the owner-selected Gmail account and existing Discord destination separately, then prove read-only scope and HTTP acceptance with consent. Research/outreach stay manual; wearables and optional external skills remain deferred. |
