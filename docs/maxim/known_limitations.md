# Known Limitations

Updated: 2026-11-17. See [current status](implementation_status.md).

- Local single-user Windows composition, not a hardened public SaaS deployment.
- Evaluation requires reviewed model-disclosable candidate knowledge and compatible
  provider access. Automated acceptance uses fixture model responses; live model
  scoring quality is a separate review.
- Native evaluation liveness remains unconfirmed unless separately checked.
- PDF content is selected approved evidence; automatic novel resume rewriting and
  optional Hiring Panel critique are not prerequisites or silently enabled.
- Public feed discovery is Greenhouse/Lever/Ashby board-specific, not universal
  LinkedIn/Indeed/Workday or whole-web coverage.
- No browser executor or automatic submission is active. S6 owns supported visible
  browser assistance; final submission remains manual.
- Gmail S7, durable Discord S8, canonical networking/analytics S9 and interview
  preparation S10 remain stage-gated. Existing external connections are not product
  authorization or delivery proof.
- Candidate and application cutovers are explicit, independent user operations.
  Native offline reads are labeled projections, not fresh database truth.
- Application pages contain 50 rows, with exact older UUID deep links; evaluation/
  packet/action responses have explicit bounded history. Migration/projection
  bounds fail visibly rather than silently dropping records.
- Source erasure removes unsubmitted derived evidence; submitted action history,
  raw import captures, journals and backups have separate deliberate retention.
