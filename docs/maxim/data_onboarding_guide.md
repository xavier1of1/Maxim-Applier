# Data Onboarding Guide

Candidate information enters through the
[reviewed Candidate workspace](reviewed-onboarding.md), not legacy runner defaults
or environment-derived answers. Upload authorized PDF/DOCX/MD/TXT or confirm typed
facts individually. Review extraction, permissions, sensitivity and corrections.
Only explicit candidate cutover makes native CV/profile files read projections.

Use [Answers](answer-memory.md) for questions and approved reusable responses.
Use [application migration](application-lifecycle.md#6-review-legacy-data-before-switching-ownership)
for old Markdown/SQLite/history/artifact records; raw import never approves facts
or packets and does not infer application outcomes.

Keep credentials in Settings/private runtime, not source files or public docs.
The complete manual input/account checklist is
[Operational setup](../../roadmap/operational-setup.md).
